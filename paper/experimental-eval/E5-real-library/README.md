# E5 — Coverage on a real library

**Question.** What fraction of a realistic C++ API can be exposed
automatically, and why does the remainder fail?

**Claim under test** (paper §9): a member a backend cannot represent is
*skipped*, with a recorded reason, rather than emitted as something that fails
to compile. That claim is cheap to satisfy on a synthetic library built to
satisfy it. E5 points the pipeline at an unmodified third-party library that was
never written with binding in mind, and reports both what bound and what the
run cost in broken promises.

## The subject, and why

[**PMP**](https://github.com/pmp-library/pmp-library) — the Polygon Mesh
Processing library — unmodified, at whatever revision is vendored under
`$PMP_ROOT/extern/pmp`. It was chosen over geogram, the other real library this
repo has a working project for, on two grounds:

- **Independence.** Geogram is a co-author's library. No amount of careful
  method fixes what that looks like to a reader.
- **It is small enough to bind exhaustively.** ~160 declared entities against
  geogram's ~460 exported ones. That is the decisive difference: at PMP's size
  arm A can bind *everything* and report the result stratified, so a reader who
  disagrees with the denominator can compute their own. At geogram's size the
  experiment would be pushed back into curation, which is the bias it exists to
  avoid.

The trade is real and worth stating: geogram declares its public surface with an
export macro (`GEOGRAM_API`), so its frame needs no judgement at all. PMP has no
such macro, so the frame is defined here — but it is defined *mechanically*, by
the compiler, and published in full.

## Running it

```sh
./run.sh              # both arms, ~2 min
./run.sh exhaustive   # one arm
./run.sh clean
PMP_ROOT=/path/to/pmp-rosetta ./run.sh
```

Needs `clang-p2996` and `bin/rosetta_gen`, plus a system C++ compiler for the
enumeration step. No Python / Node / JDK / emsdk: like E1–E3, E5 never leaves
the generation stage, because `coverage.json` is written before anything is
compiled.

## Method

### The frame (`enumerate.py`)

The denominator is the whole difficulty. "What fraction of an API binds?" is
only a measurement if somebody other than the experimenter decides what the API
*is*. So the frame is read out of clang's own AST — every class, class
template, enum and free function declared in namespace `pmp` by a header under
`src/pmp/`, excluding `viewers/` (OpenGL). `-ast-dump-filter=pmp::` restricts
the dump to that namespace; what comes back is the compiler's answer to "what
did this library declare", which is the same argument the paper makes for
reflection over a third-party parser, turned on the experiment's own instrument.

Two properties of the frame matter downstream:

- **Templates are in it.** A class or function template cannot be named in a
  manifest, so it can never bind. Filtering templates out of the frame would
  raise every percentage below without changing one fact.
- **Every entity carries its declaring header**, and the strata are built from
  that. Grouping by header is mechanical — no judgement is made here about which
  classes are the interesting ones. That judgement is exactly what arm B makes
  and arm A exists to avoid.

### The two arms

| arm | manifest | who chose the entries |
|---|---|---|
| A `exhaustive` | generated by `genmanifest.py` from the frame | nobody |
| B `curated` | the real hand-written `pmp-rosetta/manifest.json` | its author |

Both emit the same ten targets from the same rosetta, so curation is the only
independent variable. `retarget.py` rewrites arm B's infrastructure keys
(targets, include paths, module name) and drops build-stage keys the generation
stage never uses; `classes`, `functions`, `out_params`, `sequences` and every
other selection or tuning key are copied verbatim.

Arm A is mechanical with exactly two concessions, both reported rather than
hidden:

- **Signatures for overloaded names.** `^^pmp::centroid` is ill-formed once the
  namespace declares that name twice, so a bare entry would not fail to bind, it
  would fail to *compile*. Those entries carry a signature taken from the AST
  and namespace-qualified. No human picks which overload is meant.
- **Base-before-derived ordering.** rosetta requires a base class to be listed
  before classes that derive from it, and header declaration order does not
  guarantee that. `genmanifest.py` topologically sorts using the inheritance
  edges the AST supplied.

### What the driver compile is for

`run.sh` does **not** swallow a driver build failure. Compiling the emitted
generator is where a class the walk cannot handle would surface — as a build
error, which is precisely the outcome §9 says should not happen. A non-zero exit
there fails the run, because that failure is the finding.

## Two instrument defects this experiment found

E5 could not be measured as designed until both were fixed, and both are worth
recording as results about the coverage artifact rather than about PMP:

1. **`coverage.json` did not record free functions at all.** Every backend
   tracked class members and nothing else, so on a library whose algorithms are
   free functions over one data structure — 99 of PMP's 120 nameable entities —
   the report covered the wrong fifth of the API. `note_bound_function` /
   `note_skip_function` and a per-target `"functions"` array were added, and
   every backend E5 measures now calls them. Validated against emitted output:
   the python backend records 64 bound free functions and its `auto_pybind.cpp`
   contains exactly 64 `m.def(` calls.
2. **The `typescript` backend declared free functions with no visibility gate.**
   Methods were gated; free functions were emitted unconditionally, so the
   `.d.ts` promised functions the N-API module it describes does not bind —
   the one thing its own source comment says it must not do. It now applies the
   same rule the method loop uses.

A residual known limitation, reported rather than papered over: `typescript`
re-implements node's marshalling gates approximately rather than sharing them,
so it still declares 90 free functions where `node` binds 82. The gap is
narrower than the 91-vs-82 it was, but it is not closed.

## Threats to validity

- **One library.** PMP is modern, clean, C++17, and free-function-oriented. A
  template-heavy or macro-heavy API would give different constants and possibly
  a different shape. The stratified tables are published so the result can be
  re-read under a different denominator, but they cannot substitute for a second
  library.
- **The frame excludes `viewers/`.** That directory needs an OpenGL context and
  is not the library's data-processing API. It is a judgement, it is the only
  one in the frame, and it is stated in `frame.json`.
- **Coverage counts entities, not usefulness.** Arm A binds strictly more than
  arm B on every target, but that does not make it the better binding: arm B's
  `out_params` and `sequences` produce nicer signatures for the members it does
  bind, and it omits machinery (property containers, handles, iterators) a
  script user would never call. E5 measures reach, not quality, and the two
  point in opposite directions here.
- **Member counts are not comparable across all targets.** `typescript` and
  `dynamic` record bound fields; the language backends record methods only. The
  function columns are recorded identically everywhere and are the comparable
  ones.
