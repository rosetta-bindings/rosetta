# Changelog

All notable changes to **rosetta** are documented here.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). This project has not yet cut a tagged release, so entries are grouped by date rather than by version number. Dates are `YYYY-MM-DD`.

## [Unreleased]

### Removed
- **The seven *thin* backends are gone — `python`, `nanobind`, `node`, `wasm`, `julia`, `csharp` and `java` now mean what `*-expanded` meant.** Each of these languages shipped two backends: a reflection-driven one whose generated code called back into rosetta's visitors, so building the *binding* also needed the clang-p2996 toolchain, and an expanded one that wrote every call out and built with a stock compiler. Nothing was gained by keeping both — the expanded half was a superset in practice, and the thin half was where features went to be missing: extension methods were never visible to it, and an overloaded free function could only be *skipped* there, because `^^GEO::mesh_union` is ill-formed once the name is declared twice. Deleted: 14 backend files and the 14 reflection visitors that only they used (`nanobind_visitor.h`, `python_visitor.h`, `node_visitor.h`, `wasm_visitor.h`, `julia_visitor.h`, `csharp_visitor.h`, `java_visitor.h` and their `.hxx`), ~4800 lines. `csharp_runtime.h`, `java_runtime.h` and `node_runtime.h` stay — the surviving backends use them — as do the `json` / `qt` / `qml` / `imgui` / `rest` visitors. The shared halves the expanded backends had been borrowing from their thin siblings moved with them: the pybind11 trampoline emitters (`virtual_methods` / `trampolines_of`, used by python AND node), the N-API ones, the whole C# and Java wrapper surface (both backends always emitted the SAME `.cs` / `.java` / `pom.xml` / `.csproj`; only the native side differed), and `nb_bound_base`. **`rest` is now the only backend whose generated code splices reflections**, which is the one place `cpp26_root` still reaches a target.
- **Migration is a no-op for existing manifests.** The `*-expanded` spellings stay registered as aliases sharing the same backend instance, and `rosetta_gen` folds them to the short name when it reads the manifest — necessary, because everything downstream keys off that string: the output directory, the per-language build recipe, the wheel check. Without the fold a `"nanobind-expanded"` target would have generated into `bindings/nanobind/` and then looked for `bindings/nanobind-expanded/` to build. **Output directories follow the short name** (`bindings/python/`, `bindings/nanobind/`, …), so a tree generated before this change has stale `*-expanded/` directories to remove. `examples/trampoline-python` and `examples/trampoline-node` carried checked-in thin output that included the deleted visitors; both were regenerated, and their standalone CMake builds dropped the clang-p2996 toolchain block along with the reflection flags — the pybind11 one now builds and passes with a stock compiler.

### Fixed
- **nanobind bindings register their base class.** `nb::class_<arch::UserRemote>` said nothing about `UserRemote : BaseRemote`, so the two were unrelated Python types and `Model.addRemote(UserRemote(...))` — a trivially valid C++ call — failed with "incompatible function arguments". Every derived class was affected, not just one: the IR has carried `GenClass::bases` all along and the pybind11, embind, jlcxx and sol2 backends already consumed it; the nanobind ones simply never did, so *no* inheritance was registered across all 65 `nb::class_<>` in a typical module. New `gen_detail::nb_bound_base()` applies nanobind's own three rules — an unbound base is dropped (nanobind resolves a base by looking the type up in the module), a base whose class has a non-public destructor is dropped (those are in the IR but never emitted), and **at most one base survives**, because `nb::class_<T, Ts...>` extracts a single `Base` and static_asserts that no argument is left over: nanobind has no multiple inheritance where pybind11 and sol2 do, so a second bound base is reported on stderr rather than emitted into code that cannot compile. A class emitted before its own base is flagged at generation time too, since nanobind would otherwise fail at *import*. New `tests/base_classes.cpp` (7 gtests) covers the registration half of inheritance, where `tests/inheritance.cpp` covers the member-flattening half — the two are independent, and every member can be present while the conversion still fails.
- `collect_members` now enumerates through `access_context::unchecked()`
- **A class with a non-public destructor is skipped, not compiled.** `GEO::Logger` derives from geogram's `Counted` and protects `~Logger`, and every runtime backend destroys what it wraps — pybind's holder, node's `delete ptr_`, sol2's usertype. Listing one in the manifest therefore failed the BUILD, with the error pointing inside `<__memory/unique_ptr.h>` rather than at the class the user asked for. New `GenClass::is_destructible` (from `std::is_destructible_v<T>`, filled by the walk), consumed by the five expanded emitters: the class is skipped with a note naming it. A non-owning holder (`py::nodelete` and its per-backend equivalents) would bind such a class properly and is a feature of its own; failing the build was the one option that helped nobody.
- **A `compile_definitions` value may contain quotes.** `"GEOGRAM_VERSION=\"1.10.1\""` — the ordinary shape of a version define — was emitted into the driver inside a plain `"..."` literal, which ended at the value's own first quote and broke the generated `main`. Emitted as a raw string literal now, like the `module_init` statements next to it.
- **A class-typed return whose class is not bound no longer binds (python- / node-expanded).** `GEO::CSGCompiler::builder()` returns a `GEO::CSGBuilder&` that no manifest lists, and both backends bound it: pybind11 threw "Unable to convert function return value to a Python type" on the first call, and **node took the whole process down** with a fatal N-API error — `to_napi` builds its wrapper through `ctor_ref<T>()`, which for an unregistered class is an empty `FunctionReference`. `wasm-expanded` and `lua-expanded` had asked the right question all along (`wx_is_bound` / `lx_is_bound`); the other two now do too, so all four agree on what a class-typed boundary requires. The python family exempts `std::` spellings, since `<pybind11/stl.h>` and its siblings cover `map` / `pair` / `tuple` / `optional` / `variant` / `array`, none of which is a bound class either; node has no such exemption because its runtime marshals exactly string, bool, number, vector, enum and registered classes. On geogram this drops 10 members from the Python surface — `MeshFacets::begin/end/corners/vertices/triangles` and friends, iterator ranges every one of which threw when called — and turns a crash into a skip recorded in `coverage.json`.
- **An overload whose exact signature has no spelling is skipped rather than emitted.** A member that needs the disambiguating `static_cast` needs its signature spelled in C++, and `display_string_of` renders a type with no name of its own — a lambda's closure type, an unnamed struct — as `(anonymous type)` / `(lambda at …)`, which is documentation. `GEO::MeshFacets::adjacent()` returns a `transformed_range` whose second template argument is a lambda type, so regenerating geogram's bindings after the overload-support change emitted `static_cast<GEO::transformed_range<GEO::index_range, (anonymous type)> (GEO::MeshFacets::*)(unsigned int) const>(…)` and the build failed — a *compile* error, where every other gate in rosetta produces a skip. New `gen_detail::sig_spellable()`, consumed by the python / wasm / lua method gates (node already refused overloads outright): the spellable overload of `adjacent` binds, the unspellable one is dropped. Only members that need the cast are affected — everything else is spelled `&T::name`, which names no types at all.

### Added
- **Out-parameters — `"out_params": {"AttributesManager::get_doubles": [1, 2]}`.** `bool get_doubles(const std::string&, vector<double>& out, index_t& dim)` returns three things the C++ way, and every backend skipped it: the argument a runtime converts is a temporary, which cannot bind to a non-const reference. The adapter that already exists for foreign containers is where the fix belongs — declare a LOCAL, pass that, and hand its value back with the return value — so the per-backend work was small and the shapes are each language's own: a **tuple** in Python (pybind11/nanobind marshal `std::tuple`), Lua's own **multiple returns** (sol2 unpacks the same tuple), an **array** in JS (a new `to_napi` branch for tuples on node; embind marshals no tuple, so wasm builds an `emscripten::val` array instead), and a declared tuple type in `typescript`. A marked parameter leaves the exposed signature entirely; a foreign-container output arrives flattened to its boundary array like any container return. **Never inferred, and that is the design**: `void assign_points(vector<double>& pts, index_t, bool steal)` takes its vector as an INPUT it steals from while `get_doubles` fills its own as an OUTPUT, and the two are the same C++ — guessing drops an argument in one direction or a result in the other. An unmarked mutable reference keeps binding exactly as before, a mark on a `const` reference does nothing, and a mutable reference to a bound CLASS is left alone (it already crosses as a handle the callee writes through). Two gates had to catch up for the geogram case to work end to end: **python-expanded** was still refusing a non-copyable class returned BY REFERENCE, a rule the `reference_internal` fix had already superseded; and **node-expanded** / **wasm-expanded** now hand out a reference to a bound class the way their member-object properties do — an aliased wrap pinned to the receiver (new `Wrap::call_method_alias`) and a borrowed handle under `allow_raw_pointers` respectively — rather than copying it. New `tests/out_params.cpp` (9 gtests). This is the field that emptied geogram-rosetta's `src/`: with `mesh.facets.triangulate()` (geogram fan-triangulates identically) plus `facet_corners.vertex_indices()` replacing one extension method and `attributes().get_doubles(...)` replacing the other, **the hand-written glue is gone** — python, node and lua build and run the full example against geogram's own API, unchanged output.
- **`module_init` — the manifest can say what runs when the module LOADS.** A library is more than its API, and rosetta had no way to say so. geogram wants `GEO::initialize()`, seven `CmdLine::import_arg_group()` calls and a C-function-pointer registration (`nlPrintfFuncs`, routing OpenNL's `printf` through its Logger) to have happened before anything works — none of it expressible as "bind this name". The workaround was a hand-written `georo::initialize()` bound as an ordinary function, which every script had to remember to call first, and which silently poisoned everything downstream when forgotten. The new field takes the statements themselves (`{"headers": [...], "statements": [...]}`, or a bare array for statements alone) and splices them **verbatim** at the top of the module entry point — `PYBIND11_MODULE` / `NB_MODULE` / `Init` / `EMSCRIPTEN_BINDINGS` / `luaopen_*` / `JLCXX_MODULE` — before any binding is registered, so an I/O handler an init call installs is in place before the bound loader that needs it can be reached. `headers` land ahead of the bound classes' own includes, since an init statement usually names a namespace they never mention; a trailing `;` is optional and never doubled. Emitted by every backend with a module entry point (python, nanobind, node, wasm, lua, julia — thin and expanded alike); the C#/Java/REST/Qt/documentation backends ignore it, having no single load-time hook. Deliberately **not** parameterizable: this is fixed start-up work, and anything a caller should vary still belongs in a bound function.
- **`generated_headers` — a header the bound library's own build system would have produced.** rosetta compiles a library's sources without running its build, so a header that build *generates* is simply missing: geogram's `<geogram/version.h>`, configured by its CMake from `version.h.in`, had to be faked by a checked-in copy that then shadowed the real one and had to be kept in sync by hand. A manifest entry now names the `template` (with CMake's `@KEY@` placeholders) plus `substitutions` — or literal `content` lines — and the finished text is written to `<bindings>/include/<path>`, whose directory goes **first** on every generated target's include path, ahead of the library's own sources where a stale copy may sit. Substitution happens when the manifest is read, so a missing key is reported against the manifest (`no substitution for @VORPALINE_VERSION@`) instead of compiling a literal `@KEY@` into the binding; only `@KEY@` is recognised, since `${KEY}` would collide with the shell and CMake expansions such templates carry. Together with `module_init` this emptied geogram-rosetta's `src/algorithms.{h,cpp}` and deleted its `version.h` stand-in — verified by building and running the python, node and lua examples end to end with no `initialize()` call anywhere.
- **`std::filesystem::path` marshals as a string, and `std::shared_ptr<T>` reaches the caster-less backends — a factory API binds everywhere.** Two independent gaps that met in one signature: `std::shared_ptr<Mesh> compile_file(const std::filesystem::path&)` bound on **no** target, and the workaround was a hand-written wrapper taking a `const std::string&` and copying the result into a caller-supplied mesh. (1) A **path** was, to the walk, an ordinary unregistered class, so every member naming one was skipped — silently, and everywhere. It is now described as `kind: "string"` with a new `GenType::is_path`, and rides the **same copy adapter** as the foreign containers: `is_adapted()` gained a third shape, with boundary `std::string`, `path{s}` in and `.string()` out (never `.native()`, a `wstring` on Windows). That single change is why `node-expanded`, `wasm-expanded` and `lua-expanded` needed no per-backend work for it. The **python family binds it natively instead** — `<pybind11/stl/filesystem.h>` / `<nanobind/stl/filesystem.h>` were missing from the emitted include block and from both thin visitors, and with them a caller passes a `str` **or** any `os.PathLike`, which a stringified boundary would have refused; `px_touches()` is the one-line policy split, mirroring how `interop` already splits caster from caster-less. (2) **shared_ptr** was described honestly (`kind` "object", `is_shared_ptr`, pointee in `element`) but only python-expanded consumed it. The gates asked the wrong question — `object` on a shared_ptr descriptor is the literal identifier `"shared_ptr"`, bound nowhere — so `wasm-expanded` and `lua-expanded` skipped every such return, and `node-expanded` did something worse: `copy_assignable` is **true** for a shared_ptr, so it bound the return and then called `ctor_ref<std::shared_ptr<T>>()`, an unregistered constructor reference, at run time. New `gen_detail::shared_pointee()` asks about the pointee instead, and `shared_pointees(c)` — hoisted out of `px_shared_holders` so the pybind holder and the embind registration are one walk asked by two frameworks — drives **embind**'s `.smart_ptr<std::shared_ptr<T>>("T_sp")`, emitted only for classes that actually travel that way. **sol2** needed only the gate (its `unique_usertype_traits` already handles the type). **N-API** needed a real feature: a third ownership mode in `Wrap`, next to "owns a new'd object" and "aliases a member of a pinned parent" — the JS object **adopts** the shared_ptr through a one-argument `External` construction path (aliasing takes two, and JS cannot forge an `External`), so the C++ object outlives the factory that made it. Deliberately **returns only**: a shared_ptr *parameter* would mean manufacturing a control block over memory the binding does not own, and node additionally restricts the pointee to untrampolined classes, since the adopting wrapper stores a `T*` where a trampoline subclass would be read back — the same restriction, for the same reason, as the aliased member-object path. `typescript` now declares the **pointee** rather than the un-defined name `shared_ptr`. New `tests/path_shared.cpp` (14 gtests) over the IR and all six emitters. Verified live on the exact `CSGCompiler` shape with a **non-copyable** pointee: python (str *and* `pathlib.Path`), node and lua each build, call both factories, and keep the returned object alive after its compiler is collected; wasm was verified in the generated source only (no emsdk here). Suite 173/173.
- **Overload selection on FREE functions — `"signature": "void(GEO::Mesh&, bool)"` on a `functions` entry.** The member-function overload work below stops at class scope; at namespace scope nothing had moved, and for the same reason it never could: `make_function<^^F>` needs a reflection of the function, and `^^GEO::mesh_union` is **ill-formed** the moment the namespace declares the name twice. So an overloaded free function was not merely dropped — the entry could not be written at all, and the only way to reach one was a hand-written wrapper under a different name (three of them in geogram-rosetta, whose only content was `mesh_boolean_operation(result, A, B, "A+B", verbose)`), plus the file, the build entry and the manifest lines that come with it. A manifest entry may now carry the **signature** of the one overload it means. Nothing about it is reflected: the new `make_function_sig<Sig>` takes the function **type** as an ordinary type argument — an overload set is never named — and `gen_detail::fn_sig_of<R(A...)>` decomposes it into the same `GenType` / `GenParam` descriptors the reflection path produces, ref and mutable-ref flags included (the parameter-shape rules live next to `params_impl` so the two cannot drift). The exposed name falls back to the tail of the qualified spelling, since there is no `identifier_of` to ask, and `expose` still wins — which is what lets the *same* name be listed twice, under two signatures, and bind both. Every backend that forms a function **pointer** disambiguates with `static_cast<void(*)(…)>(&GEO::mesh_union)` through a shared `gen_detail::fn_addr()`: pybind11, nanobind, embind, sol2, jlcxx, and — the one that needed more than a textual tweak — **node-expanded**, where the pointer is a non-type *template argument* (`napi_free_entry<&fn>`), a position in which a cast is valid and `&`-of-an-overload-set is not. The adapter lambdas the expanded backends emit for sequence parameters call through the same cast rather than by name, so the manifest's choice is not silently re-resolved on the *adapted* argument types. The five backends that splice the function's reflection (thin `node`, `rest`, `julia`, `csharp`, `java`, all emitting `bind_*_function<^^name>`) **skip such an entry with a note on stderr** — there is no reflection for one member of a set, and a skipped function is honest where an uncompilable one is not. `rosetta_gen` validates the signature's shape only (return type, balanced parentheses) and splices it verbatim, so a bad *type* is reported against the user's own spelling; `--init`'s scan still skips overloaded names, but its note now names the field that binds them. Overload selection is deliberately rejected on `extensions`: an extension reaches the backends as a `GenMethod`, whose emitters spell its address in many more places than a free function's single address-of. New `tests/free_overload.cpp` (13 gtests) pins the IR, the cast in every pointer-forming backend, the skip in the reflection-splicing ones, and that a signature-less entry's output is byte-identical. Verified end to end: two overloads of one `api::move` bound side by side into a pybind11 module that imports and calls both. Suite 159/159.
- **Overload support — a class's whole overload set now reaches the binding.** The reflection walk deduplicated member functions **by identifier**: of `at(int)` and `at(int, int)` exactly one entry reached the IR and the other vanished, with no note on stderr and nothing in the generated source to hint it had ever existed. A missing overload was indistinguishable from a method nobody asked for, which is the same silent-discard shape as the abi3 wheel and the `expose`/extension key mismatch. `collect_members` now dedups by **(identifier, function type)**, and each backend applies the policy its target can honour: pybind11, nanobind and jlcxx dispatch on argument types, so **every** overload binds; embind, N-API, sol2, the C#/Java op tables, REST routes and QML invokers key a method by name, so the **first-declared** entry binds and the rest are reported. C++ **name hiding** is preserved — a derived declaration of a name hides every base overload of it, exactly as a C++ caller sees without a `using Base::f` — and a diamond-shared base member is still emitted once. Two backends gained overloads they used to drop outright: **nanobind-expanded** (which skipped any overloaded name) and **lua-expanded** (same). The compile-time visitors get the same treatment through a new `rosetta::first_overload<T, Fn>()`, since a visitor sees one member at a time and cannot know about its siblings.
- **`coverage.json` — a machine-readable account of what bound and what did not.** Written by `generate()` to `<out_dir>/coverage.json` on every run. rosetta's conservative policy (skip what a backend cannot marshal rather than bind something that throws at call time) is correct and *silent*: users discovered that 12 of their 40 methods never made it by reading generated C++. The report records both stages — **reflection** drops that never reached any backend (operators and conversion functions, member templates, base overloads hidden by a derived declaration) and **per-target** skips with a machine-readable reason slug plus a human sentence naming the offending type. The **bound** side is recorded too, because counting only skips cannot tell "everything bound" apart from "this class never reached this backend". Committing the file makes a method that stops binding a reviewable diff instead of a runtime `AttributeError`. See [docs/COVERAGE.md](docs/COVERAGE.md).

### Fixed
- **A bound class template specialization was spelled with its template arguments stripped of every namespace, so the generated source did not compile.** `qualified_class_name()` built the C++ spelling from `std::meta::display_string_of()` whenever the type had no plain identifier — which is exactly the case for a specialization. `display_string_of` is a *display* rendering, not a C++ spelling: it drops the namespaces of every template ARGUMENT. The scope walk then prefixed the outer namespace like an ordinary identifier, so `lookup::…::Horizon<std::vector<lookup::math::Point2D>>` came out as `lookup::interpolation::implicit::Horizon<vector<Point2D, allocator<Point2D>>>` — outer name restored, arguments unresolvable. The expanded backends normally cover bare identifiers with `using namespace` directives, but `using_namespaces_of()` only collects the namespaces of BOUND types, so binding the argument types fixed the user half of the errors and could never reach the `std::` half. `ns_qualified_name()` (which fills `GenType::object_qualified`, i.e. how a field/parameter/return type is spelled) had the same fallback and the same bug. Both now go through a new `qualified_type_spelling()` that composes the template-id **structurally** — `template_of` + `template_arguments_of`, recursively, peeling cv/reference/pointer and rendering non-type arguments as their value — the way `sequence_spelling()`/`marshal_spelling()` already compose theirs by hand. Nested templates, class-nested templates and non-type parameters (`FieldND<2>`) are all exact. One subtlety the structural walk forced: libc++ declares everything in the inline namespace `std::__1` and the fork exposes no `is_inline_namespace()`, so the scope walk skips namespaces whose name is reserved to the implementation (leading underscore) — otherwise the emitted spelling would be `std::__1::vector`, valid on the generating host and broken against libstdc++ or MSVC, which defeats the whole point of the expanded backends.
- **csharp-expanded / java-expanded emitted a member pointer that could not compile for any overloaded method** — `ops.call["f"] = &rosetta::cs::call_method<&T::f>` spells the *bare* `&T::f`, which names the whole overload set rather than a function, so the generated TU failed to compile the moment a bound class overloaded a name. This predates the overload work (the single entry that reached the IR was already unbindable there) and was invisible because no test bound an overloaded method through those backends. Both now spell the member pointer through the shared `px_member_pointer()`, which casts to the exact signature when the declaring class overloads the name.
- **nanobind-expanded: the abi3 wheel was *tagged* but not *built* — `Development.SABIModule`** — packaging emitted a wheel tagged `cp312-abi3` whose payload was `<lib>.cpython-3XX-<plat>.so`, a filename only the exact interpreter that built it ever looks for. pip believes the tag, so the wheel installed cleanly on every CPython ≥ 3.12 and then failed at **`import`** with `ModuleNotFoundError` on all but one of them — the worst shape this can take, since neither the build nor the install reports anything wrong and the artifact looks correct right up to the point someone else uses it. The two halves the `pyproject.toml` comment insists must move together — `wheel.py-api = "cp312"` and `cmake.define.ROSETTA_STABLE_ABI = "ON"`, both behind the same `if.python-version = ">=3.12"` predicate — *were* moving together; what was missing is a third, silent precondition on the CMake side. nanobind **discards a `STABLE_ABI` request without a word** when the `Python::SABIModule` target does not exist (`nanobind-config.cmake`: "Stable ABI builds require CPython >= 3.12 and Python::SABIModule" — `set(ARG_STABLE_ABI FALSE)`, no message), and that target is only defined when `Development.SABIModule` is among the requested components; the template asked for `Interpreter Development.Module`. So the option was set, accepted and dropped, `nanobind_add_module(… STABLE_ABI …)` quietly produced an ordinary per-version module, and scikit-build-core stamped `abi3` on it anyway — the tag is decided by `pyproject.toml` and never cross-checked against what CMake actually built, which is precisely why the mismatch survives to the installing machine. The component is now requested as **`OPTIONAL_COMPONENTS`, deliberately not `REQUIRED`**: PyPy and free-threaded builds have no stable ABI, and nanobind already degrades to a per-version module there, so requiring it would turn a working build into a hard configure failure in order to fix a case those interpreters cannot reach. Only `nanobind_expanded_backend.hxx` is touched — the thin `nanobind_backend.hxx` carries the same `find_package` line but has no `STABLE_ABI` path and no `pyproject.toml`, so it cannot hit this. Verified end to end through a **real regeneration**, not a patched output tree: `find_package` now reports `Development.Module Development.SABIModule`, the nanobind target becomes `nanobind-static-abi3`, the payload becomes `<lib>.abi3.so`, and ONE wheel built with **3.13.12** installs and imports under **3.12.13, 3.13.12 and 3.14.5** — which is what docs/MANIFEST.md ("one artifact covers every later interpreter") has been promising all along. The plain non-packaging `cmake -S . -B build && cmake --build build` path configures and builds unchanged. Found while binding a fuzzy-inference library, whose wheel imported on the machine that produced it and nowhere else. **No regression test added**: the failure lives in the interaction between the emitted CMake, nanobind's own config and scikit-build-core's tagging, which the render-level suite does not reach — pinning it would mean building a wheel and importing it under a second interpreter.
- **A class nested inside another class is spelled fully qualified (`GenClass::qualified`)** — the enum fix below, one level over and in the same place it was missed. `GenClass` carried only `name` + `name_space`, and `gen_detail::qualified_of()` rebuilt the C++ type as `name_space::name` — but `class_namespace<T>()` stops at the first non-namespace scope, so a `struct TemporalDeriv` declared inside `sift::ParsedModel` reports **no** namespace at all and the reconstruction collapsed to the bare identifier `TemporalDeriv`. That is not a name the emitted code can resolve — backends open namespaces with `using namespace` and cannot open a class — so listing a nested class in `classes` produced `nb::class_<TemporalDeriv>(m, "TemporalDeriv")` and `&TemporalDeriv::baseVar`, and the generated binding failed to compile with "unknown type name 'TemporalDeriv'; did you mean 'sift::ParsedModel::TemporalDeriv'?". `GenClass` gained a **`qualified`** field, filled by the walk from `qualified_class_name<T>()` (namespaces *and* enclosing classes), and `qualified_of(const GenClass&)` now prefers it, falling back to the old `name_space::name` reconstruction when it is empty — so hand-built `GenClass` values in tests and direct `render()` callers keep working. Because no backend spells a bound class as a C++ type without going through `qualified_of`, the single-point fix reaches every one of them, exactly as the `GenEnum::qualified` change did. Worth knowing *why this had to be a nested class to bite*: an enum nested in a class was fixed earlier and a nested type appearing only in a **signature** was fixed earlier still (`exact_spelling()` re-qualifies the bare token), so the one surviving hole was the class *declaration and member pointers* of a nested class listed in its own right — which nothing had asked for until a manifest needed `ParsedModel::TemporalDeriv` bound as the return type of `FuzzyParser::parseTemporalDerivFragment`. Until then that method bound happily and threw at call time ("Unable to convert function return value to a Python type"), the familiar shape of an unbound type in a bound signature.
- **`qualified_class_name<T>()` handles a class template specialization** — surfaced immediately by the fix above, because that routed **every** bound class through the helper rather than only the handful of nested enums. It opened with an unguarded `std::meta::identifier_of(dealias(^^T))`, and a class template *specialization* has no plain identifier: for `sift::SpatialFieldND<2>` the call is not a constant expression, so the enclosing `consteval` lambda stopped being one and the build died on `constexpr variable 'n' must be initialized by a constant expression` — pointing at the helper, with nothing about templates in the message. The leaf now takes the same guard `class_name()` has used all along (`has_identifier(ty) ? identifier_of(ty) : display_string_of(ty)`), which yields the unqualified template-id `SpatialFieldND<2>` for the scope walk to prefix like any other identifier. ### Fixed
- **A non-const `T&` return no longer binds as a COPY (python- / nanobind-expanded)** — pybind11 and nanobind both copy an lvalue-reference return under their automatic policy, and for a fluent API that is silently wrong twice over. `Interpolator &addValueConstraint(const Point &, double, double)` returning `*this` handed Python a **copy** — `interp.addValueConstraint(...) is interp` was `False`, so anything done through the returned handle landed on a temporary — and paid for the copy on **every call**, including the constraint vector the call had just grown, which turned an ordinary accumulate-in-a-loop into quadratic work. Measured on a real binding (interpolate3d, 20³ grid): **14 µs per call at 8 grid nodes rising with the object, 3.66 s for a 50k-point loop**. Emitters now attach `py::return_value_policy::reference_internal` / `nb::rv_policy::reference_internal` (`reference` for a static) when `GenMethod::ret_is_ref` is set, the return is a **bound class**, and `ret_cpp` does not start with `const` — same numbers after: **0.11 µs per call, 5.5 ms for the loop** (~665x), and `is interp` now `True`. The IR needed nothing new: `ret_is_ref` was already recorded (for the non-copyable-return skip) and the exact `ret_cpp` spelling carries the constness. **Const references keep copying, deliberately** — Python has no notion of constness, so binding `const Knob &peek() const` by reference would hand scripts a freely mutable view of what the C++ API declared read-only; the copy is the honest reading there. `std::shared_ptr` returns are excluded too (the holder owns that lifetime question), and raw-pointer returns keep the policy they already had. Extension methods get it as well, since a fluent extension (`Cls &fn(Cls &, …)`) has exactly the same shape. ### Fixed
- **wasm templates: manifest `link_options` land after the template's own link flags** — both wasm backends spliced `{{USER_DEFS_BLOCK}}` right after `target_include_directories`, i.e. *before* the template's base `target_link_options` — but emcc honors the **last** occurrence of a repeated `-s` setting, so a manifest `link_options` entry could never override a template default (`-sALLOW_MEMORY_GROWTH=0` silently lost to the base `=1`). The block now splices after the base flags, making overrides effective. Why one would: memory growth backs the heap with a resizable ArrayBuffer, which `TextDecoder` rejects ("must not be resizable") when embind decodes a C++ exception's `what()` — `-sALLOW_MEMORY_GROWTH=0 -sINITIAL_MEMORY=…` restores readable exception messages (found binding PMP, whose triangle-only algorithms throw on quad meshes). Caveat documented in MANIFEST.md; note the wasm-expanded base flags already export `FS,NODEFS` — re-adding `-sEXPORTED_RUNTIME_METHODS=FS` in `link_options` would now *drop* the NODEFS export (last one wins).
- **Expanded backends: nested class types are spelled fully qualified** — `display_string_of` prints a class nested inside another class by its bare identifier (`Planes` for `stressinv::NodalPlane::Planes`), and the emitted code opens namespaces (`using namespace`) but cannot open classes, so any constructor or trampoline signature naming a nested type (`NodalPlane(vector<Serie>, Planes, Planes, double)`, `StressDomain(…, const Axis&, …)`) failed to compile. `exact_spelling()` now re-qualifies the bare token with the full parent chain — enclosing namespaces *and* classes (new `qualified_class_name<T>()`, which unlike `class_namespace()` keeps walking through outer class scopes). Subtlety worth recording: the type reaches the helper through `std::remove_cvref_t`, an alias template, and `^^U` then reflects the *alias* — whose `parent_of` is the alias's own scope, not the class's owner — so the reflection must be `dealias`ed before walking parents.
- **Constructor parameters of std-namespace types are spelled by value — dangling-view fix** — the ctor spellings in `ctor_param_cpp` were exact (`const std::vector<double>&`), and every expanded backend reproduced them verbatim in `init<...>`. Two problems: bindings pass *caster temporaries* for std types (a Python list / JS array converts to a temporary `std::vector`), so a constructor that *stores* the reference captured freed memory — `Serie(values, 3).count()` returned garbage because nanobind's first-match dispatch handed every call to the `const std::vector<double>&` **view** ctor instead of the owning `&&` one; and the `const&`/`&&` pair bound as two indistinguishable overloads. New `ctor_param_spelling()`: a parameter whose decayed type lives in namespace `std` is spelled by value (routes construction to the move overload — never dangles, no extra copy), while user class types keep their exact spelling (they arrive as references to live registered objects, and a class may deliberately store that reference, e.g. a domain object referencing its model). Constructors whose spellings collapse to the same list dedupe to one IR entry.
- **The walk skips `std::initializer_list` constructors** — no target language can produce one (no marshaller in any backend), its exact spelling doesn't round-trip (`initializer_list<double>`, unqualified), and such a constructor always shadows an equivalent `std::vector` overload. `is_exportable_constructor()` now rejects any ctor with an `initializer_list` parameter, in all backends at once (`initializer_list` also added to `qualify_std`'s table for the residual method-signature case).
- **Node: a non-default-constructible class is constructible from script** — the `Wrap` constructor's parameterized path default-constructed the inner object then *assigned* the ctor-table result into it, so a class whose only constructors take arguments (every stressinv data class: `Joint`, `Striation`, `GPS`, `StressDomain`…) threw "this class cannot be constructed directly" — previously only reachable as a member-object alias. The Wrap now falls back to building the object *straight from the ctor-table entry into fresh storage* (move/copy construction, no default-construct-and-assign), gated on the new `GenClass::copy_or_move_constructible`; the emitter registers entries for a default-constructible class when it is assignable (unchanged) and for a non-default-constructible one when it is move- or copy-constructible.

- **Per-class `"final": true` manifest flag — suppress the trampoline** — a class marked final is treated as non-overridable from the host language: no `Py_T` / `Js_T` trampoline is generated even when it has public virtual methods (they still bind as ordinary callable methods). Two motivations: skipping useless shims for classes nobody script-subclasses, and — the geogram case — making a virtual-bearing class eligible as a **node member-object property**: the aliased wrap stores a `T*`, which requires the wrapped type to be `T` itself, so `GEO::MeshVertices` / `MeshFacets` (public `delete_elements` / `permute_elements` / `pop` virtuals from the `MeshElements` interface) can now be reached as `mesh.vertices` / `mesh.facets` under node too. Flows as `ClassEntry::final_` → generated driver `opt.final_classes` → `GenClass::is_final`; `virtual_methods()` / `node_virtual_methods()` return empty for a final class, which every trampoline-emitting backend already keys on. (`tests/member_object.cpp`: with/without-final node render pair + python.)
- **Foreign sequence containers (`rosetta::is_sequence` trait + manifest `sequences` field)** — a library's own vector type (`GEO::vector<T>`, an aligned/pooled vector) now crosses the boundary like a `std::vector` of its element. Registration is opt-in: `"sequences": ["GEO::vector"]` in the manifest (rosetta_gen emits the `rosetta::is_sequence<GEO::vector<T>>` specialization into `bindings.h`), or the specialization written by hand for programmatic use (new header `rosetta/sequence.h`; requirements: default-constructible, `value_type`, `size()`, `resize(n)`, `begin()`/`end()`; elements arithmetic / `bool` / `std::string` / bound enum). The IR keeps `kind` "unknown" (the `is_pointer` / `is_callback` pattern — backends that don't opt in keep skipping the type) and records `GenType::is_sequence`, the element, and a **composed qualified spelling** `seq_cpp` (`GEO::vector<double>` — `display_string_of` prints template names unqualified, so the spelling is rebuilt from the enclosing namespaces + the template identifier + the element). The opted-in backends — **python- / nanobind- / node- / wasm- / lua-expanded**, plus **typescript** declarations (`number[]`) — marshal by COPY through a `std::vector<element>` boundary inside an emitted adapter (python/nanobind/wasm/lua: lambda; node: a namespace-scope free function the runtime's `fn_traits` introspect, bound through `ext_method` / `call_static` / `napi_free_entry`; wasm registers the boundary vector; lua emits a `sol::overload` pair accepting BOTH container userdata — what a bound sequence return pushes — and plain tables via `sol::nested`). Three deliberate consequences: a **mutable `Seq&` parameter binds input-only** (the adapter's local is a real lvalue — geogram's `assign_points(vector<double>&, dim, steal)` works, `steal` steals from the adapter's copy); an **overload set whose surviving (first-declared) IR entry is the sequence overload binds** — the adapter calls by NAME with concrete arguments instead of spelling the ambiguous `&T::name`, which is exactly the `MeshVertices::assign_points` / `MeshFacets::assign_triangle_mesh` shape; and a **virtual method naming the container keeps its trampoline override off** (`sig_type_bindable` now rejects registered sequences — the exact spelling can't round-trip through `qualify_std`, which would mis-qualify it to `std::vector` and break the override; the method still binds callable — this was the "trampoline spelling of GEO::vector virtuals" blocker that kept `MeshVertices` / `MeshFacets` out of geogram's manifest). Sequence-typed public fields bind as copying properties (python/nanobind/wasm/lua). Verified end-to-end on geogram: `mesh.facets.assign_triangle_mesh(3, coords, tris, false)` from a Python list builds the mesh, round-tripping exactly against the flat-array extensions (`tests/sequence.cpp`, 8 gtests; suite 54/54).
- **Member-object properties on wasm-expanded** — the non-copyable member object of a bound class (`GEO::Mesh::facets`) now binds under embind too, as a **borrowed-handle getter method** (`mesh.facets().nb()`): embind properties copy, so the emitter binds `.function("facets", +[](Mesh &s) { return &s.facets; }, emscripten::allow_raw_pointers())` — a non-owning pointer handle to the member living inside the parent. Unlike pybind's `reference_internal` nothing pins the parent (embind has no keep-alive policy) — the handle dangles if the mesh is destroyed first; same clash rule as python (a method of the same name wins). **lua-expanded needed no change** — sol2 pushes a class member by reference, so the member object already rode the ordinary readonly member-pointer path — but is now covered by tests. With this, all four runtime backends expose `mesh.facet_corners`-style sub-objects, except node's trampolined-class case (`MeshVertices` / `MeshFacets` have virtuals; node's aliased wrap stores a `T*`, not a `Js_T*` — unchanged).
- **Member-object properties — a class's non-copyable member objects become reference properties** — a public data member whose type is another *bound* class but is not copyable (it holds a back-reference to its owner, like `GEO::Mesh::vertices` / `facet_corners`) used to be skipped wholesale by the copyability gates; the geometry it carries was only reachable through hand-written extension functions. It is now bound as a **read-only property returning a reference to the real member**, with the parent object kept alive for as long as any child handle exists. **python-expanded** emits `def_property_readonly` with a reference-returning lambda and `py::return_value_policy::reference_internal`. **node-expanded** reworks the runtime `Wrap` to hold its object **by pointer in one of two modes** — *owned* (the ordinary `new Cls()` path) or *aliased* (the new `get_member_object<&Cls::member>` accessor wraps the member's address and pins the owning JS object in a persistent reference); a pleasant side effect is that a **non-default-constructible class is now wrappable at all** (its JS constructor throws "reached as a member of another object" instead of failing to compile), where the old by-value `Tramp inner` storage required default-constructibility of every bound class. **typescript** declares the property (`readonly facet_corners: MeshFacetCornersStore;`). On a name clash (e.g. a manifest extension already named like the field) the method wins and the property is skipped; node additionally restricts the alias to untrampolined member classes (the stored pointer is a `T*`, not a `Js_T*`). **wasm- / lua-expanded** still skip such fields (follow-up). Verified end-to-end on geogram: `mesh.facet_corners.nb()` / `.vertex(c)` alias the live store in Python and Node, including keep-alive after the last mesh reference is dropped and GC runs (`tests/member_object.cpp` plus geogram's `test_member_object.{py,js}`).

### Fixed
- **Overload sets no longer break the expanded builds** — the member walk dedups overloads by identifier (one IR entry survives), but the expanded emitters spell the bare `&T::name` member pointer, which is **ambiguous** for an overload set — binding any class with a const/non-const accessor pair (`GEO::MeshVertices::point_ptr`, `point_coordinates`, …) failed to compile. A new reflection-time `GenMethod::is_overloaded` flag (more than one exportable member function of the declaring class shares the name) lets **python- / node- / wasm- / lua-expanded** skip the whole set, and **typescript** hide it, keeping the declarations aligned with the runtime surface. Conservative by design — overload selection by explicit signature in the manifest is the planned lift.

### Changed
- `node_runtime.h` now holds only the documented declarations (plus the small compile-time trait types they need); the implementations — the conversion helpers, the override plumbing and all of `Wrap`'s member definitions — moved to `backends/inline/node_runtime.hxx`, included at its bottom (the `generate.h` / `inline/generate.hxx` layout convention, as previously done for `annotate.h`).

### Fixed
- **Out-of-line side-car: scientific notation in numbers** — the consteval JSON parser had no exponent support, so a `"range": [1e-10, 1e-6]` (a routine solver tolerance) parsed as `[1, 0]` **and silently derailed every key after it** — later members lost their doc/range/combobox entirely. `to_double` / `number()` now consume `1e-10`-style exponents.
- **Emitted range bounds lose tiny magnitudes** — `num_str` rendered bounds via `std::to_string`, which collapses `1e-10` to `0.000000`; generated validating setters and docs (all backends) then carried a wrong bound. Now formatted with `%g` (`1e-10` stays exact).

Because ImGui is immediate-mode, the generated `draw_<Class>()` functions run every frame and bind widgets *directly to the live members* — the object is the single source of truth, no copies, no signal plumbing. The widget kit lives in the new header-only, reflection-free `rosetta/visitors/imgui_runtime.h` (the ImGui `qt_widgets_runtime.h`); the generated app builds with a stock C++20 compiler. `ROSETTA_IMGUI_FRAMES=N` auto-exits after N frames for headless smoke tests / CI. The `widget::spin` / `widget::textfield` hints select a typed input box (clamped when ranged) over the slider/drag default. `examples/geom-expanded` gained the target (`geom_imgui`, out-of-line annotations, stock build), and the new **`examples/imgui`** binds a stock-C++ copy of the shared `Algo` demo class with every annotation out of line in `Algo.ann.json` (`doc` / `range` / `combobox`), so the inspector builds with a stock C++20 compiler (`./run.sh`; the inline-annotated original stays at `examples/Algo.h`).
- **Julia backend, expanded variant (`julia-expanded`, CxxWrap / jlcxx)** — brings Julia up to the python-expanded feature level, and fixes the thin backend's biggest gap: building against the *stock* libc++ (no clang-p2996) lets `<jlcxx/stl.hpp>` compile, so **`std::vector` members, parameters and returns are fully bound** — including vectors of bound classes (`getSurfaces() → StdVector` of `Surface`), which the thin `julia` target must skip entirely (fork libc++ gap). Registration is two-phase (all `add_type`s, then members — jlcxx resolves signature types eagerly, so `Model::addSurface(Surface&)` would otherwise fail when `Surface` is registered later). Covers constructors with exact spellings (plus an `ArrayRef` factory variant so `Surface([0.0,0,0,…], Int32[0,1,2])` takes plain Julia `Vector`s, zero-copy view), fields as `name(obj)` / `name!(obj, v)` with `readonly` / validating `range`, methods with exact-signature `static_cast` disambiguation (dropping `noexcept`, which jlcxx's templates don't match), an `ArrayRef` overload per numeric-vector parameter, statics as module functions, extension methods, single inheritance via `jlcxx::SuperType` + `julia_base_type`, free functions, raw pointers to bound classes, and the copyability gates (an lvalue-ref class/vector return is wrapped in a by-value-copying lambda, matching pybind's `automatic` policy). Enum constants are prefixed with the enum name (`Kind_Point`) — Julia module constants share a flat namespace with the types, so a bare `Point` enumerator collides with a bound `Point` class ("Duplicate registration"). Emits `auto_jlcxx.cpp`, a CMakeLists that locates JlCxx through `CxxWrap.prefix_path()`, and a `<lib>.jl` loader module. Callbacks (`std::function` params) stay skipped — jlcxx has no Julia-closure → `std::function` conversion. `examples/geom-expanded` gained the `julia-expanded` target (`jlgeom`) and `example_julia.jl` exercising the vector round-trips, range validation and the free function.
- **Lua backend (`lua-expanded`, sol2)** — a 25th backend: fully-expanded [sol2](https://github.com/ThePhD/sol2) bindings emitting a `require`-able C module (`luaopen_<name>`, built as `<name>.so`) for Lua 5.1–5.4 / LuaJIT with a stock C++17 compiler; sol2 is fetched automatically at configure time (an installed package wins). Covers constructors (full runtime overload resolution — no embind-style one-per-arity limit), fields (readonly / validating `range` properties), methods with exact-signature `static_cast` disambiguation, statics, extension methods (free function bound as instance method), enums (`new_enum`, read-only), free functions, bound-class raw pointers (non-owning), `std::function` callbacks (a Lua function converts natively — no adapter shim), and multiple inheritance via `sol::bases<...>` (embind is single-base). `std::vector` crosses both ways: a returned container is reference-semantics userdata (`#v`, `v[i]`, in-place mutation of the C++ object), and any signature naming a vector gets a second, table-accepting overload (`sol::nested`) so plain Lua tables work too — writable vector *fields* get a type-branching setter accepting either form. An lvalue-ref class return is pushed by reference (no copy), so non-copyable classes keep more surface than under pybind/embind. Note: sol2 does not support Lua 5.5 (changed C API); the generated CMake prefers a 5.4 installation and warns on 5.5+, and the emitted `luaopen_` guards with `luaL_checkversion` so loading the module into a mismatched interpreter (e.g. Homebrew's default `lua`, now 5.5) raises a clean "version mismatch" error instead of segfaulting. `examples/geom-expanded` gained a `lua-expanded` target (`luageom`) and an `example_lua.lua` exercising table-constructed Surfaces, the `std::function` callback, range validation and the enum table.
- **Extension methods (`extensions` manifest class field)** — a class entry may list free functions whose **first parameter is `Cls&` (or `const Cls&`)**; each is exposed as an ordinary *instance method* of the bound class, with the receiver dropped from the exposed signature and the method named after the function's unqualified identifier. This is the escape hatch for a library whose own members can't cross the boundary — raw-pointer accessors (`GEO::Mesh`'s `point_ptr()` returns a bare `double*`), attribute-template lookups, overloaded helpers (`mesh_load`/`mesh_save`) — without a hand-written wrapper class: the glue shrinks to stateless free functions and scripts keep holding the real C++ objects (`mesh.set_surface(coords, tris)` calls `georo::set_surface(mesh, …)`). `generate()` validates the receiver parameter and splices the function into the class IR (`GenMethod::is_extension` / `ext_qualified` / `ext_header`; `GenerateOptions::extensions` / `GenExtension` for programmatic use). **python-expanded / nanobind-expanded** bind the free function directly (pybind/nanobind treat a `T&`-first free function as a method); **wasm-expanded** likewise via embind; **node-expanded** calls it through a new `Wrap::ext_method<FP>` that passes the wrapped object as receiver; the text backends (**typescript / markdown / html**) render it as a normal method. Backends that can only emit member pointers (qt / qml / C# / Java / REST) skip extensions explicitly; the thin (reflection-re-running) backends don't see them.
- **Copyability captured in the IR, and emitters gate on it** — every runtime backend copies at some boundary (pybind's `def_readwrite` setter and its `automatic` policy on an lvalue-ref return, embind's `.property` accessors and class returns, N-API's `to_napi` construct-and-assign), so a class whose copy is deleted made the *generated code fail to compile*. The reflection walk now records `std::is_copy_constructible` / `is_copy_assignable` per type (`GenType::copy_constructible` / `copy_assignable`, false for incomplete types), whether each parameter is an lvalue reference and whether it is a *mutable* one (`GenParam::is_ref` / `is_mutable_ref`), whether a method returns an lvalue reference (`GenMethod::ret_is_ref`), and whether the class itself is assignable (`GenClass::copy_or_move_assignable`). The **python- / nanobind- / node- / wasm-expanded** emitters then skip exactly what they could not compile — a non-copyable public field (e.g. `GEO::Mesh::vertices`, a member object holding a `Mesh&` back-reference), a method returning a reference to a non-copyable class (`Mesh::get_subelements_by_index`), a by-value parameter of one, and (node/wasm) a *mutable non-class reference* out-parameter (`std::string&`, `index_t&` — the converted argument is a temporary, which can't bind to a non-const reference). **typescript** applies the same visibility rules so the declarations match the runtime surface. A by-reference class parameter is exempt everywhere — it never copies. Net effect: a class like `GEO::Mesh` binds directly as an opaque handle plus its marshalable methods instead of breaking the build.

- **Per-target `link_options` manifest field** — an object-form target may list extra linker flags (`{"lang": "wasm-expanded", "link_options": ["-lnodefs.js"]}`), emitted as `target_link_options(... PRIVATE ...)` in *that* target's generated CMakeLists only. Per-target — unlike `compile_definitions` — because link flags are toolchain-specific: e.g. emscripten's nodefs library is needed when the bound code mounts NODEFS under Node, but would break a native link. (`TargetSpec::link_options` / `GenContext::link_options` for programmatic use.)
- **`compile_definitions` manifest field** — preprocessor definitions (`"NAME"` or `"NAME=VALUE"`) applied to the generator driver *and* every compiled binding target via `target_compile_definitions(... PRIVATE ...)`, so the reflection walk, the bound headers and the `user_sources` all see the same preprocessor state. Typical use: a third-party library's configuration switches, e.g. geogram's `GEOGRAM_USE_BUILTIN_DEPS` (use the vendored libMeshb / rply / zlib instead of system libraries) and `GEOGRAM_WITH_HLBFGS` (compile the HLBFGS optimizer in). Ignored by the text-only backends. (`GenerateOptions::compile_definitions` / `GenContext::compile_definitions` for programmatic use.)
- **C sources in `user_sources`** — entries may now be `.c` files (e.g. vendored zlib / rply / libMeshb / OpenNL); the generated binding CMakeLists then calls `enable_language(C)` automatically so they compile alongside the C++ binding (native backends and the wasm templates alike).
- **Node / WebAssembly: JS-function callbacks are marshalled into `std::function` parameters** — a method or constructor taking a `std::function<R(A...)>` (e.g. `UserRemote(fn, isStress)` for a per-point far-field stress, `Solver::onMessage` / `onEnd` progress callbacks) now accepts a host-language function, wrapped into the C++ `std::function` and invoked synchronously (valid for callbacks fired during a host-initiated call such as a `solver.run()`). The neutral IR gained `GenType::is_callback` plus a decomposed `callback_sig` (`[0]` = return type, kind `void` when none; `[1..]` = parameter types), populated in `type_descriptor`. A callback is bound only when its whole signature is convertible — scalars, `bool`, strings, enums, `std::array` (element-wise), vectors of such, and bound classes — so a callback naming a raw pointer, an unbound by-value type, or a nested callback (e.g. `Triangle*`, `Eigen::VectorXd&`, an unbound `StepResult&`) is still skipped rather than breaking the build. **Node** makes `napi_supported<std::function<…>>` true for a convertible signature and materializes the callback with `from_napi`, keeping the JS function alive in a shared `Napi::FunctionReference`; `std::array` gained an N-API array conversion. **WebAssembly (expanded)** emits an `emscripten::val` adapter — a factory-lambda constructor `+[](emscripten::val, …) -> T*` or a receiver-first method lambda — plus a `rosetta_wx` helper (`to_val` / `from_val` / `make_fn`) inlined into the generated TU (embind can't marshal a `std::function` parameter directly). (Python already handled this via `pybind11/functional.h`.)
- **Node / WebAssembly: raw pointers to bound classes are marshalled** — a method returning `T*` (e.g. `Model::addSurface() → Surface*`) or taking one (e.g. `Model::addRemote(BaseRemote*)`, `Postprocess::burgersFor(Surface*)`) is now bound, as a *non-owning* handle to the C++ object (the C++ side keeps ownership). The neutral IR gained `GenType::is_pointer` (with the pointee identifier). **WebAssembly (expanded)** emits `emscripten::allow_raw_pointers()` on any signature naming a raw pointer, gated so only a pointer to a *bound* pointee is accepted (a vector-of-pointer is still skipped — embind has no `register_vector<T*>`). **Node** wraps a returned `T*` by retargeting a fresh wrapper's `self_` at the external object; `Wrap` now holds its owned value in a `unique_ptr` (via a heap-constructing ctor table) so a non-default-constructible type (`SeidelSolver(Model&)`) or an abstract referenced-only base (`BaseRemote`) works, and all member access goes through a `self_`-based `obj()` so owned and referenced wrappers behave identically. A pointer to a forward-declared class is left unsupported (completeness is required).
- **Python / WebAssembly: C++ inheritance is registered** — a bound class now declares its bound base classes to the target framework, so a derived instance is accepted wherever a base pointer/reference is expected (e.g. passing a `UserRemote` to `Model.addRemote(BaseRemote*)`, or a `Coulomb` where a `Tic` is wanted) and the hierarchy is visible to the host language (`issubclass` / prototype chain). Direct public bases are reflected into `GenClass::bases` (via `std::meta::bases_of`) and each backend filters them to the bases that are themselves bound. **Python** threads them through `bind_pybind` into `py::class_<T, Bases..., Trampoline>` (multiple bases; trampolines compose). **WebAssembly (expanded)** emits `emscripten::class_<T, emscripten::base<Base>>` (embind supports single inheritance, so the first bound base is used). Bases must be registered before their derived — which follows from manifest order; a base that isn't bound is simply omitted. (Node is not yet covered: node-addon-api `ObjectWrap` does not compose C++-base inheritance across separately-wrapped types without a dedicated prototype-chain shim.)
- **`rosetta_gen --init` flag** — writes a fully-commented example `manifest.json` (default `./manifest.json`, or a path argument) so a new project can start from a working template instead of the docs. The example exercises the common fields: `cpp26_*` toolchain overrides, an array-form `user_include`, `rosetta_include`, `generator_name` / `module_name`, `user_sources`, a representative spread of `targets`, and one example class and one example function. It **refuses to overwrite an existing file** — warning and exiting non-zero instead — so a hand-written manifest is never clobbered.
- **`user_sources` manifest field** — a list of user `.cpp` files compiled directly into every generated binding target via `target_sources(...)`. Use it when the bound headers only *declare* the API and you want the bodies built into the binding rather than linked from a pre-built `user_lib`. Works alongside or instead of `user_lib`; ignored by the text-only backends. Entries may be **shell globs** (e.g. `src/algorithms/*.cpp`), expanded at generation time; results are sorted and de-duplicated.
- **Multiple include directories** — `user_include` now accepts an array of directories (a class `header` is searched across all of them, like a compiler's `-I` order), in addition to the existing single-string form.

### Fixed
- **Generator link no longer requires the bound class's constructor** — `IRVisitor::field` default-constructed a `T tmp{}` to read *every* field's default value, odr-using `T`'s constructor; since the driver links no user library, a class with a header-declared constructor (`GEO::Mesh`) failed at link time. The instance is now built only for field kinds `default_value_str` can actually render (arithmetic, enum, `std::string`) — class-typed fields never produced a default anyway.
- **Node: the `Wrap` constructor compiles for non-assignable classes** — its parameterized-constructor path assigns the freshly built object into the wrapper's inner storage, a statement that failed to compile for a class with deleted copy *and* move assignment even though the emitter registered no such constructor. The path is now `if constexpr`-guarded on assignability (matching the emitter's gate, `GenClass::copy_or_move_assignable`), so such a class keeps its default constructor and everything else compiles out.
- **Node: wrapped class arguments are handed to C++ by reference, not by copy** — `from_napi<T>` now returns `T&` for a wrapped class type (the C++ object living inside the JS object's `Wrap`) instead of a by-value copy. A bound function taking `T&` or a pointer out-parameter therefore mutates the caller-visible JS object, and a type whose copy is shallow or deleted (e.g. a pImpl facade — the copy duplicated the impl pointer and dangled it when the temporary died) no longer breaks. Scalars, strings, enums and vectors still convert by value.
- **WebAssembly (expanded): several build breakers for a real library** — the expanded embind backend now (a) sets `CMAKE_CXX_STANDARD 20` (arch3-style headers use concepts); (b) marshals a by-value class only when it is a *bound* `class_` — an unregistered/incomplete object (`std::array`, `std::initializer_list`, a forward-declared helper returned by value) is skipped instead of aborting the build; (c) emits no constructor for an abstract class (`GenClass::is_abstract`, so embind never tries to allocate one); (d) disambiguates the member-function pointer with an explicit `static_cast` to the exact signature, so an overloaded method no longer trips embind's "no matching function"; (e) emits at most one constructor per arity (embind dispatches constructors by parameter count and throws at registration on a collision — e.g. `Vector3(double)` vs `Vector3(const std::vector&)`). With these, a real library (arch3) builds, links and runs under embind.
- **Node: by-value class marshalling requires a round-trippable type** — the N-API conversion default-constructs a wrapper and copy-assigns, so a class returned/taken by value is now supported only when it is complete, default-constructible and copy-assignable (a non-copyable/incomplete helper like `Model::regions()`'s `ModelRegions` is skipped rather than breaking the build). Pass such types by pointer instead.
- **Python / Node: trampoline override signatures resolve unqualified `std` names** — a trampoline reproduces each virtual's *exact* parameter spelling via `display_string_of`, which drops the `std::` qualifier (e.g. `vector<double, allocator<double>>`), so the generated override failed to compile. The trampoline block now emits a `using namespace std;` scoped to its own `rosetta_py` / `rosetta_node` namespace — enough for the spellings to resolve, with no leak into the binding-registration code or user headers.
- **Python / Node: trampolines skip virtuals they can't marshal** — a virtual method whose signature has no caster (a raw C array, or a pointer the host language can't round-trip — Node-API has no conversion for a bare pointer at all) would make `PYBIND11_OVERRIDE` / `napi_call_override` fail to compile. A new reflection-time `GenMethod::sig_bindable` flag (rejects arrays, all pointers, and `std::vector`-of-pointer — the conservative common denominator across backends) lets the trampoline omit those overrides; a concrete bound class still supplies the body, so the trampoline stays instantiable.
- **Python / nanobind / WebAssembly / Qt / QML: unbindable members no longer break the module** — a method, static method, or field whose return type, a parameter type, or (for a field) its type can't be represented by the target framework now gets skipped instead of aborting the whole build. The two compile-breakers are **raw C arrays** (e.g. a method returning `double (&)[3][3]` — pybind11 / nanobind / embind have no caster, and the Qt / QML backends can't declare `R r` nor round-trip it through `QVariant`) and **types only forward-declared in the binding TU** (pybind needs `sizeof` / `typeid` / `is_polymorphic` on the complete type). A consteval `*_bindable_type` / `*_bindable_fn` guard drops exactly those, matching the support guards the Node, Julia, Java, C#, and REST backends already had. The guard now also covers **constructors** (`py::init<>` / `nb::init<>` / embind `constructor<>` over an unrepresentable parameter no longer aborts the build).
- **Python / nanobind / WebAssembly / Qt / QML: a pointer is judged by its pointee, and `std::vector` by its element** — the previous guard treated any pointer as bindable, but `sizeof(T*)` is always valid so a pointer to an *incomplete* type slipped through and then broke the build inside the framework's caster (it still needs the pointee's `typeid` / `sizeof` to register the conversion). The `*_bindable_type` concept now checks the **pointee** for completeness, and recurses into a `std::vector`'s **element** type (so a `std::vector<T*>` of an incomplete `T` is rejected just like a bare `T*`). A method / field / constructor that names such a type is skipped instead of failing to compile.
- **Python / nanobind / WebAssembly / Julia: the synthesized default constructor was registered behind a runtime `if`** — `bind_*` fell back to registering `T()` with `if (!saw_default_ctor && std::is_default_constructible_v<T>)`. A plain `if` still *instantiates* the discarded branch, so the framework's default-construct (`py::init<>()`, `nb::init<>()`, embind / jlcxx `constructor<>()`, and ultimately `new Trampoline{}`) was compiled even for a non-default-constructible type — a hard error for classes / trampolines whose only constructors take arguments (e.g. a `Surface(Model*, …)` or a pybind trampoline over such a base). Switched to `if constexpr` so the fallback is only instantiated when the type is actually default-constructible. (The Java and C# backends already used `if constexpr`; the Node backend has no such fallback.)
- **Node: reference parameters of bound types** — the N-API backend materialized every argument by value (`from_napi<remove_cvref_t<P>>`), so a non-const lvalue-reference parameter couldn't bind and any function taking a bound type by reference (e.g. an algorithm taking `SurfaceMesh&` and mutating it in place) failed to compile. A new `arg_from_napi<P>` binds reference parameters of wrapped user types directly to the wrapper's persistent `inner` object, so in-place mutations propagate back to the JS object (and `const T&` no longer copies). Applied to free functions, instance/static methods, and constructors.
- **Node: unbindable free functions are skipped, not fatal** — a free function whose signature can't cross the N-API boundary (a pointer out-parameter such as `std::vector<T>*`, a `std::function`, an unsupported return type, …) previously broke the whole module build. `bind_napi_function` now guards on a consteval `napi_free_supported<F>()` and binds a stub that throws on call instead, so the module still loads and every other function stays usable.
- **Template-specialization type names** — `class_name<T>()` no longer hard-errors when a bound free function takes or returns a template specialization (e.g. `pmp::Matrix<float, 3, 1>`, `Eigen::SparseMatrix<double>`); it falls back to the full display spelling when the type has no plain identifier.
- **Operator / conversion members** — the member walk skips functions without an identifier (`operator==`, `operator[]`, `operator T`), which can't be bound by name to a target language and previously broke generation for such classes.
